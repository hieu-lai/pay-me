Decision points to react to

1. Provisional webhook projection

A verified lifecycle event updates the visible state quickly, but it remains “provisional” until GET confirms the current provider resource. Is that the right balance of speed and truth?

2. No timestamp wins

Delivery ID and event ID deduplicate evidence. Provider publish time is retained but never used as a winner. A suspicious or late transition triggers GET; a confirmed irrevocable state is never reopened by webhook alone.

3. Bounded reconciliation

Waiting agreements check every 30 minutes, active or suspended agreements get a daily safety-net check, conflicts check now, and six failed GETs or 24 hours without a successful check moves tracking to operator review. Confirmed terminal states stop.

4. Two operator-facing axes

“Waiting”, “ready”, “recoverable”, and “ended” describe the provider lifecycle. Separately, “current”, “checking”, “retrying”, and “operator review” describe tracking health. Normalized evidence and dedupe keys live with the agreement; raw webhook bodies never do.

Normalized evidence

Newest first. The raw signed body exists only long enough to verify and parse it. Invalid signatures are counted as security rejects, not trusted agreement evidence.
